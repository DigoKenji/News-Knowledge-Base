### Workers
The titles "looking inside the workers" and "scaling from what the workers report" show that workers are a topic in their own right in this series. The article does not say what a worker is in Muru.

> 🔎 Added context: A worker is a process that runs application code and handles requests. Several workers can run side by side so that one slow request does not block the others.

### Canary releases
The post "canaries without a service mesh" and the post "releases, not restarts" both concern how new code reaches running traffic. A canary release sends a small share of traffic to a new version first, so a fault affects fewer users before it is caught. > 🔎 Added context: A service mesh is an infrastructure layer that usually handles traffic routing and observability between services. It is not described in the article beyond the title.

## 🧠 Mental models
### Experience sets the bar, not the tool
**The model:** Generated output is only as good as the standard applied to it. The person who knows where things go wrong decides whether the output is acceptable, even when a tool produces most of it.
**How to apply it:** Before accepting AI-written code, name who owns the quality decision and what past failures they use to make it.
