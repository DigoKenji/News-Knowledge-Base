## Part 1 — New draft concepts (4)

- [ ] **D01 · [Storage engines: LSM-trees and B-trees](/concepts/data/storage-engines-lsm-btree.md)** — The two main ways databases organise data on disk - log-structured merge trees (append, then merge sorted files in the background) and B-trees (update fixed-size pages in place) - with LSM-trees usually faster for writes and B-trees for reads.
  - Sources: 3 (DDIA + 2 paper/standard/docs)
  - Fix: 
- [ ] **D02 · [Schema evolution and data compatibility](/concepts/data/schema-evolution.md)** — Changing the structure of data over time without breaking readers or writers - keeping backward compatibility (new code reads old data) and forward compatibility (old code reads new data), usually with schema-based encodings such as Protocol Buffers, Thrift or Avro.
  - Sources: 3 (DDIA + 2 paper/standard/docs)
  - Fix: 
- [ ] **D03 · [Transaction isolation levels](/concepts/data/isolation-levels.md)** — How far a database shields concurrent transactions from each other - from read committed and snapshot isolation to full serializability - each level preventing more anomalies (dirty reads, lost updates, write skew) at a higher cost.
  - Sources: 3 (DDIA + 2 paper/standard/docs)
  - Fix: 
- [ ] **D04 · [Event sourcing](/concepts/backend-systems/event-sourcing.md)** — Storing an application's state as an append-only log of immutable domain events ("order placed", "item shipped") and deriving current state by replaying them, instead of overwriting records in place.
  - Sources: 3 (DDIA + 2 paper/standard/docs)
